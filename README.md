# 墨閱 Inkread

讓 Markdown 回到好閱讀。繁體中文介面，支援本機文件、好讀的表格、Mermaid 圖表與 LaTeX 公式；所有文件在瀏覽器內處理。

1.7.1 起，側欄優先顯示「我的文件」，三份內建教學收在下方預設收合的「使用範例」。需要時點一下展開；搜尋到範例名稱時會自動展開，清除搜尋後恢復原本收合狀態。

1.7.5 保存實際文字區塊及段內位置，調整視窗寬高、手機直橫向切換與不同尺寸離線重開會回到同一段；文件庫備份亦攜帶此定位。既有舊進度開啟後會補上區塊定位，未記錄舊視窗的歷史進度仍依原方式恢復。手機測試使用瀏覽器視窗模擬，不代表實機驗收。

1.7.4 修正字級改變後的閱讀位置：先依保存時的字級找回段落，再以目前字級接續同一段；也適用舊版 16 自動升 18 與完整離線重開；手動調整後保存的進度也記住原字級。進度備份另外保留原字級，既有備份仍可使用。

1.7.2 起提高介面文字與對比，主要按鈕及文件名稱使用 14px，輔助文字至少 12px；新使用者正文預設為 18px。段落與清單不再比所選字級縮小，表格及程式碼也調大。1.7.3 起，舊版保存的 16px 自動升為 18px，其他字級保留。新版另行記錄手動調整，即使調回 16px，重新開啟仍會保留；上方加減鈕可調成 13–22px。舊版沒有記錄是否手動調整，因此舊版手動選回的 16px 也會升為 18px。

## 直接使用

[開啟線上墨閱](https://koviankevin.github.io/inkread/) · [下載離線網站 ZIP](https://koviankevin.github.io/inkread/inkread-offline.zip) · [GitHub 原始碼](https://github.com/koviankevin/inkread)

線上版首次開啟時會在背景下載完整離線功能。等頁首顯示 **「可離線使用（含圖表與公式）」** 後，同一瀏覽器可斷網重新整理、關閉後重新開啟此網址，並首次使用圖表與公式。下載不完整會顯示重試，請保持連線直到完成。清除網站資料、換瀏覽器／使用者設定檔，或瀏覽器回收網站儲存空間後，需要重新連線下載。

1.4.0 起，匯入／貼上的文件、本機圖片、最後開啟的文件及每份閱讀位置會自動保存在此瀏覽器。等另一個保存狀態顯示 **「文件、圖片與進度已保存在此瀏覽器」**，離線重開即可接續閱讀，不需重新匯入。文件清單的清除按鈕會刪除保存的文件、圖片與進度，並同步到其他墨閱分頁；不會刪除硬碟上的原始檔。

從 1.3 或更早版升級時，舊頁面只把文件放在記憶體，無法事後取回。先保留原始文件，關閉所有舊版分頁，重新開啟確認為 v1.4，再匯入一次；之後會自動保留。

1.5.0 起可在左側按 **「備份文件庫」**，下載一個 `.inkread` 檔，帶走所有匯入／貼上的文件、本機圖片、最後開啟的文件與各文件的閱讀進度。將檔案搬到另一台電腦或瀏覽器，開啟墨閱後按 **「還原文件庫」** 選取備份、核對數量，預設合併並保留目的地文件庫，也可明確選擇整庫取代；取消、損壞備份或儲存交易失敗都不會刪除原文件庫。

備份與還原皆在本機處理，可完全離線使用，也支援解壓縮後的 `file://` 版。新電腦仍需先下載並解壓縮程式，或連線開啟網站等到「可離線使用」。備份不包含程式本身、範例、主題字級偏好、遠端圖片檔或其載入許可；遠端圖片還原後仍須主動允許。`.inkread` 含文件原文與圖片，**未加密**，請妥善保管。格式以 SHA-256 檢查檔案完整性，並遵循現有文件／圖片數量與容量限制。

| `.inkread` 格式 | 何時使用 | 還原相容性 |
| :--- | :--- | :--- |
| 版本 1 | 文件庫未含改名連結對應時，v1.7.0 以上仍輸出此格式 | v1.5.0 起支援；v1.7.0 以上可繼續讀取舊備份 |
| 版本 2 | 文件庫含改名連結對應（例如「保留兩份」後） | **需要墨閱 v1.7.0 以上**；較舊程式會拒絕，請先更新目的地網站或離線下載版 |

備份雜湊使用瀏覽器原生 Web Crypto，請以 HTTPS、localhost 或解壓縮後的本機版本使用備份與還原；一般 HTTP 內網頁面會提示改用這些方式。

**1.7.0 保留兩份**：同路徑衝突可選「保留兩份」，目前版本保留原名，備份版本自動命名為 `檔名 (備份 1).md`，名稱已存在就繼續編號。確認前會列出實際新名稱。同路徑圖片也自動保留兩份，讓目前文件與備份文件各自使用原本圖片；各自閱讀進度、備份文件之間的連結也保留。原始 Markdown 文字不變，改名對應保存在文件庫內，離線重開及再次備份／跨瀏覽器還原都會帶入。圖片也可單獨選擇保留兩份。

**1.6.0 合併還原**：選取備份後，預設使用「合併文件庫，保留現有資料」。目前獨有的文件、圖片與閱讀進度會保留，備份裡不重複的內容會加入。以**完整路徑**判斷衝突，不同資料夾裡的同名文件可共存；相同路徑的文件與圖片會逐項列出，需選擇「目前版本」、「備份版本」或「保留兩份」才能確認。可展開比較文件前 2,000 字元、閱讀進度與圖片；選哪份文件，就保留該份的閱讀進度，圖片另行選擇。即使文字相同，也能決定保留哪個進度。

若要整個替換，切換為「取代整個文件庫」；會明確提示清除目前資料。合併後超過容量上限時會阻止操作，不會略過部分檔案。預覽期間其他分頁若已保存新的變更，確認時會重新檢查並要求再次選擇，避免以過期快照覆蓋。取消或交易失敗都會保留原文件庫。1.5 的 `.inkread` 格式版本 1 可繼續使用。

下載並解壓縮 **inkread-offline.zip**，雙擊 `index.html` 即可使用。不需要 Node.js、帳號或網際網路。也可以把解壓縮後的所有檔案放到內網靜態網頁伺服器；請保留目錄結構，並確保 `.js`、`.css`、`.woff2` 字型可被讀取。

- **開啟文件**：拖曳或選取 `.md`、`.markdown`、`.txt`。可一次開啟多份文件。
- **匯入資料夾**：選擇文件與圖片的共同上層資料夾，依相對路徑顯示圖片及切換 Markdown 連結。也支援拖曳資料夾。
- **貼上文字**：點擊「貼上 Markdown」，或在閱讀區直接貼上；預覽前可修改文字與檔名。
- **備份／還原**：左側文件庫按鈕將整個閱讀空間存為 `.inkread`，可搬到其他電腦／瀏覽器。
- **閱讀調整**：左側文件清單、右側章節目錄、13–22 px 字級與亮／暗色模式。
- **程式碼**：常用語言上色與複製按鈕。
- **表格**：欄位對齊、隔行底色、長文字換行；寬表在自身區域內捲動。
- **列印／PDF**：按右上角列印圖示，使用瀏覽器列印或「另存為 PDF」。寬表格請選擇橫向紙張；列印預覽會隱藏側欄與操作介面。

鍵盤快捷鍵：`O` 開啟文件、`/` 搜尋文件、`Esc` 關閉對話框。

## 語法與圖片

支援標題、清單、引用、連結、GFM 表格、勾選清單、刪除線、程式碼區塊；以 `mermaid` 程式碼區塊繪製圖表；`$...$` 行內公式、`$$...$$` 獨立公式。隨附 `samples/` 目錄可用來驗證圖片與文件連結。

Markdown 中的原始 HTML 以文字顯示，不執行腳本。Mermaid 使用嚴格安全模式；自訂設定、點擊連結與外部圖形資源不會執行。語法錯誤的圖表保留原始文字，公式錯誤會標示在內容中。

本機相對圖片需要連同資料夾一起匯入；單獨開啟 `.md` 不會授權瀏覽器讀取其他檔案。支援 PNG、JPEG、GIF、WebP、AVIF、SVG、BMP 與 ICO。遠端圖片預設不載入，須按「允許此文件載入遠端圖片」；離線或連線失敗會顯示提示。瀏覽器可能阻擋 HTTPS 頁面中的 HTTP 圖片。

## 隱私與相容性

沒有後端、文件上傳、追蹤碼、分析或外部 CDN。文件文字、本機圖片 Blob 與閱讀位置保存在瀏覽器 IndexedDB；主題、字級及關閉前的小型進度檢查點使用 localStorage。這些資料依部署目錄區分，不會寫回原始檔或上傳 GitHub。遠端圖片及其載入許可不保存，重開仍須明確允許連線。

保存只適用於同一瀏覽器、設定檔及網站／檔案位置。清除網站資料、使用無痕模式、換電腦或儲存空間被瀏覽器回收時，資料可能不再保留；請保留重要原始文件。若儲存被封鎖或配額不足，仍可當次閱讀，但頁首會標示尚未保存並提供重試；清除失敗也不會假裝已刪除資料。

主要支援近期 Chrome 與 Edge。資料夾選取使用 `webkitdirectory`，拖曳資料夾使用 File and Directory Entries API。內容以 UTF-8 解碼；其他編碼請先轉為 UTF-8。大文件與複雜圖表的速度依裝置而異；圖表限制 50,000 字元與 500 條邊。內網環境若只允許檔案下載而不提供 HTML 網站服務，請下載後在本機解壓縮開啟。

## 開發與建置

需要 Node.js 22.12+ 與 npm。

```sh
npm ci
npm run build
npm run dev
```

建置結果位於 `dist/`，資源皆為相對路徑，可部署到子目錄或使用 `file://`。JavaScript 分為閱讀器 `app.js`、公式 `math.js`、圖表 `diagrams.js` 與佈局引擎 `elk.js`，皆為一般 IIFE 腳本，避免本機檔案的模組載入限制。公式樣式 `math.css` 與 KaTeX 字型隨包附上；請保留整套檔案。

瀏覽器整合測試：

```sh
# 安裝 Chromium 後，依環境設定瀏覽器位置
CHROMIUM_PATH=/usr/bin/chromium npm test
```

## GitHub Pages

Actions 在 PR、推送 `main` 或手動觸發時驗證：建置工作執行 CI 契約檢查、`npm audit --audit-level=low`、建置及完整 Chromium `npm test`，並平行呼叫同提交的 Firefox／Playwright WebKit 備份與合併相容性測試。只有兩組必要工作全部成功，且來源為 `main` 的推送或手動執行，才部署該次執行產生的 Pages 成品；失敗、取消或略過都不發布。PR 只驗證與產生 artifact，不部署；Chromium 每次只跑一次。離線 ZIP 打包方式保持不變。契約檢查可用 `npm run test:ci` 單獨執行，範圍與限制見 [`tests/README.md`](tests/README.md)。Playwright WebKit 是引擎測試，不代表真正 Safari／iOS 實機驗證。儲存庫的 **Settings → Pages → Source** 需設為 **GitHub Actions**。部署完成後，網站根目錄的 `inkread-offline.zip` 可供下載。

## 容量與效能

單份文件上限 2 MiB、匯入文件合計 200 份／20 MiB；單張圖片 20 MiB、圖片合計 100 MiB，每次匯入最多 1,000 份檔案。每份文件最多繪製 20 張 Mermaid 圖，每張最多 50,000 字元及 500 條邊。超長程式碼區塊保留原文與複製功能，超過 20,000 字元時略過上色。

1.2.0 將首載 JavaScript 由 5,898,968 位元組降至 366,024 位元組，減少約 94%；主程式 gzip 約 134 KB。四份 JavaScript 合計 5,531,083 位元組，較 1.1.0 減少約 6.2%。以上不含 CSS、字型與圖片；實際網路壓縮由伺服器決定。

公式或圖表接近可見區域（前後 300 px）時才載入對應程式；同份文件的同類內容會一起繪製。Mermaid 與閱讀器共用公式和淨化套件，ELK 在佈局時才載入；保留 Mermaid 12 的 ELK 預設。右上角列印按鈕會先補齊尚未繪製的內容。

1.3.0 加入 Service Worker。主程式約 368 KB（gzip 約 135 KB），完整離線資源在頁面顯示後背景下載，不會提前執行大型圖表與公式引擎。下載版仍包含所有分檔，完全斷網也能首次使用。

Service Worker 快取只包含建置時列出的網站靜態資源，包括圖表引擎、公式、60 份字型、範例與授權。逐檔校驗 SHA-256，整批成功才宣告可離線使用。文件與本機圖片另存在 IndexedDB，不混入網站版本快取，因此網站更新不會刪除文件。下載 ZIP 與遠端圖片不列入快取。

保存採增量交易：匯入時只寫變更的文件與圖片，捲動每 500 ms 最多排一次小型進度交易，不會反覆重寫整份文件或圖片。切換文件立即記住位置；恢復時先等待圖表、公式、本機圖片與字型，再依章節及節內位置校正。重新匯入不同內容會重設該文件的舊進度；相同內容保留進度。背景分頁及關閉事件另寫小型同步檢查點，降低最後一小段進度遺失的機會。

網站更新會先下載完整新版；失敗保留舊版，成功後顯示「更新已備妥」。關閉所有墨閱分頁再開啟，即套用新版，不強制重整正在閱讀的文件。新版啟用後只清除本網站的舊版本快取。回復舊版部署也會經相同的完整下載及切換流程。

線上離線快取需要 HTTPS（本機 localhost 可測試）與瀏覽器允許 Service Worker／網站儲存；一般 HTTP 內網與 `file://` 請使用完整下載版。網站根目錄及 `index.html` 入口支援離線重新開啟，請保留部署子目錄尾端的 `/`。機制背景見 [MDN Service Worker 說明](https://developer.mozilla.org/en-US/docs/Web/API/Service_Worker_API/Using_Service_Workers)。

長文件的章節位置會快取；捲動更新每個畫面幀最多一次，使用二分搜尋選取目前章節。文件解析與圖表繪製仍在主執行緒，複雜圖表仍可能短暫停頓。完整圖表引擎仍有較大的首次使用成本。

`npm test` 會執行功能驗收及安全／效能回歸；`npm audit` 查核鎖定依賴的已知弱點。GitHub Pages 部署前也會執行兩者。測試程式 `tests/audit.mjs --baseline` 可對未修改的舊版成品記錄基準，結果在 `test-results/`。

`npm run benchmark:startup` 可測量三次冷啟動中位數（gzip、5 Mbps、50 ms 延遲、CPU 四倍降速），產生 `startup-results.json`。若將舊版完整網站放在 `test-results/startup-baseline/`，會交錯比較兩版；測量指標為閱讀器顯示且標題已插入 DOM 的時間，並非全部圖表完成或實際繪製到螢幕的時間。
