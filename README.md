# 墨閱 Inkread

讓 Markdown 回到好閱讀。文件在你的瀏覽器處理與保存，支援離線閱讀、圖片、圖表與公式。

[開啟墨閱](https://koviankevin.github.io/inkread/) · [下載離線版](https://koviankevin.github.io/inkread/inkread-offline.zip) · [原始碼與問題回報](https://github.com/koviankevin/inkread)

## 開始使用

1. 開啟線上版，拖入 `.md`、`.markdown`、`.txt`，或按「貼上 Markdown」。
2. 文件有本機圖片時，匯入文件與圖片的共同上層資料夾；只選 Markdown 不會授權讀取旁邊的圖片。
3. 等頁首分別顯示「可離線使用」及「文件、圖片與進度已保存」，再斷網接續閱讀。
4. 按「備份文件庫」匯出 `.inkread`，並確認備份檔已下載。

下載版完整解壓縮後，使用近期 Chrome 或 Edge 開啟 `index.html`，可首次離線使用，不需要 Node.js 或帳號。請保留資料夾結構。一般 HTTP 內網若無法使用完整網站離線能力，請改用下載版；備份需要 HTTPS、localhost 或本機下載版支援的 Web Crypto。

## 文件庫與閱讀

- **管理文件**：重新命名或刪除單份文件。重新命名保留圖片、內文文件連結與閱讀進度；同資料夾不能使用重複名稱。原始 Markdown 及硬碟檔案不會被改寫。
- **安全刪除**：單份刪除與整庫清除都有確認，可取消。單份刪除保留圖片，避免影響共用同一圖片的其他文件；整庫清除則移除本網站保存的文件、圖片與進度。
- **排序與搜尋**：依匯入順序、文件名稱或最近閱讀排序，也能搜尋檔名。範例預設收合，不會占用你的文件清單。
- **閱讀調整**：亮／暗色、13–22px 字級、章節目錄、寬表格、程式碼複製及列印／另存 PDF。新使用者正文預設 18px。
- **分頁接續**：同一文件在不同分頁可各自保留段落。使用瀏覽器恢復原分頁、最近關閉分頁或保留網址片段的書籤接續；不含文件片段的新首頁採共用最後選檔。

網址片段只指向本機已存文件與位置，不含文件原文或圖片，也不隨 HTTP 請求傳送。轉貼網址不會傳送文件庫。重新命名後的舊分頁網址可接續同一份既存文件；已刪除或重新匯入不同內容時，舊位置會安全回退。

快捷鍵：`O` 開啟文件、`/` 搜尋、`Esc` 關閉對話框。對話框中的輸入不觸發閱讀快捷鍵。

## 保存、備份與跨裝置搬移

「文件庫狀態與備份」顯示文件／圖片數量、內容大小、匯入上限及上次產生備份的時間。內容大小不等於瀏覽器剩餘空間，也不包含程式快取。匯出紀錄只代表曾產生備份，仍需確認瀏覽器下載完成。文件或圖片變更後會建議再次備份，單純閱讀不會不斷提醒。

在新裝置先備妥墨閱程式，再選「還原文件庫」。預設合併並保留現有資料，同路徑衝突可選目前版本、備份版本或保留兩份；保留兩份會自動重新命名，保留各自圖片連結與閱讀進度。整庫取代需要明確選擇；取消、損壞備份或交易失敗不會先刪除原文件庫。

`.inkread` 包含文件原文、本機圖片與每份文件的一份進度，**未加密**，請妥善保管。它不包含程式、遠端圖片、遠端圖片許可或整組瀏覽器分頁。

| 備份格式 | 相容性 |
| --- | --- |
| 格式 1 | v1.5.0 起可讀；未含更名連結對應時繼續使用 |
| 格式 2 | 更名或「保留兩份」等連結對應需要 v1.7.0 以上 |

文件保存在同一瀏覽器、設定檔與網站／檔案位置。無痕模式、清除網站資料、更換位置或瀏覽器回收空間，都可能失去本機資料；網站更新本身不會清除文件庫。重要文件請保留原始檔並另外備份。

## 遇到問題

| 狀況 | 下一步 |
| --- | --- |
| 圖片不見 | 匯入包含文件與圖片的共同資料夾；遠端圖片需主動允許，未承諾自動離線保存 |
| 顯示尚未保存／空間不足 | 保持目前分頁開啟，先匯出備份，再確認瀏覽器允許儲存或整理內容，按重試保存 |
| 其他分頁變更文件庫，但此分頁仍有未保存內容 | 先將此分頁內容匯出備份，再重新開啟；程式保留內容供匯出，不自動覆寫其他分頁 |
| 離線準備未完成 | 保持連線並按重試；缺少的資源無法在斷網後補下載 |
| 更新已備妥 | 先確認文件已保存，再關閉所有墨閱分頁並重新開啟 |
| 舊網址找不到文件 | 確認是原瀏覽器及原網站位置；已刪除資料不會靠網址重新產生 |

「使用支援與診斷」可檢視及複製版本、開啟方式、功能狀態、數量與大小；不包含文件內容、檔名、圖片、網址片段或閱讀段落，不會自動送出。回報問題前請核對將提交的資訊，避免附上私密文件。

## 格式、限制與支援範圍

支援標題、清單、引用、GFM 表格、勾選清單、刪除線及程式碼上色。以 `mermaid` 區塊繪製圖表，以 `$...$`／`$$...$$` 顯示公式。原始 HTML 顯示為文字，不執行其中腳本；圖表與公式錯誤保留可閱讀的回退。

- 文件以 UTF-8 解碼；單份最多 2 MiB，最多 200 份／20 MiB。
- 本機圖片單張最多 20 MiB，圖片合計最多 100 MiB；每次匯入最多 1,000 個檔案。
- 圖表限制 50,000 字元、500 條邊；大型文件與複雜圖表的速度依裝置而異。
- 主要支援近期桌面 Chrome、Edge；其他引擎結果以對應版本的驗收紀錄為準。WebKit 引擎與手機 viewport 模擬不等同 Safari／iOS 或實機驗收。

## 開發與驗證

需要 Node.js 22.12+。

```sh
npm ci
npm run build
npm run dev
```

測試命令以 `package.json` 為準：`npm run test:ci` 驗證選測與部署關卡，`npm test`／`npm run test:compat` 為完整手動入口；日常修改由 CI 選擇受影響案例。相同完整來源與合併基準已在 PR 驗證成功時，main 沿用結果，重新建置並部署本次產物。完整政策見原始碼中的 `TESTING.md`。

每次驗收需記錄實際來源、瀏覽器／環境、案例及結果；舊版本綠燈或測試檔存在，不代表新版本已通過。功能選測、完整冷啟動、備份二次搬移與失敗回滾的細節見原始碼的 `tests/README.md`。

GitHub Pages 的 Source 使用 GitHub Actions。PR 不部署，必要驗證失敗或取消時會阻擋發布；只有正式分支的部署工作取得 Pages／OIDC 寫入權限。
